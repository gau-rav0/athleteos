# Phase 1 architecture

The implementation contract is CODEX_TASK.md and PHASE1_PRD.md. No Phase 2–6 calculations or screens are implemented.

`android/core` is a JVM 17 Kotlin module with no Android or Samsung dependency. It defines the canonical raw envelope, identity, source policy metadata, source/store boundaries and sync engine. `android/app` supplies Health Connect, Room, HTTPS/Supabase Auth, WorkManager and Compose. Raw records from each provider remain independent.

Foreground synchronization runs on a worker dispatcher. Health Connect snapshots persist pages of at most 100 records immediately; only source IDs accumulate across pages. Checkpoints and missing-record reconciliation commit after the complete snapshot and final permission checks succeed. A failed later page leaves earlier records queued safely without advancing the checkpoint or inferring deletions. Room reconciliation reads source IDs first and loads a raw payload only when a tombstone is needed, avoiding full-history payload materialization.

Samsung SDK snapshots also persist each page before reading the next; production SDK reads request at most 25 records because exercise/sample payloads can be dense. The bridge retains only source IDs between pages and preserves its upsert-only snapshot reconciliation policy. The SDK-enabled APK includes the Kotlin Parcelize runtime explicitly: a local AAR cannot supply its Maven transitive dependency metadata.

Compact raw payloads may occupy up to 1.75 MiB, leaving room for the envelope within Android's ordinary 2 MiB SQLite cursor window. Android, both offline importer paths, the Edge Function and migration 0004 enforce the same limit. Larger or malformed records remain quarantined privately. Sync retries quarantined source IDs through the original provider; a successful normalized upsert removes its quarantine entries only in the same transaction that persists the raw record and durable queue revision. Missing IDs cannot create synthetic deletions during this retry.

Local identity includes the authenticated account and a length-delimited provider/type/vendor-ID tuple. Room partitions records, queue, cursors, quarantine and runs by account. Records and queue revisions are committed in the same transaction as change tokens. Acknowledgements match the uploaded revision, preserving edits made during upload. Source cursors represent durable local receipt, not network receipt; an outage leaves the upload queue intact.

Bootstrap creates the source change token before reading the initial snapshot. Every type has its own token. Expiry creates a fresh token before a full readable snapshot and checks previously known IDs. Snapshot reconciliation can create tombstones only when the source certifies complete start-time membership in the actual readable interval, after all pages and a permission recheck succeed. A failed read never implies deletion. Normal sync reconciles 72 hours; once daily or manually it reconciles seven days.

The backend derives ownership from a validated Supabase Auth JWT. An atomic SQL RPC persists devices, up to 500 raw records and redacted run metadata. Historical imports use the same envelope/provider/IDs and endpoint, with an ingestion-origin flag. Source policy is metadata only; steps are never summed between phone and watch.

Samsung Health Data SDK 1.1.0 is supplied locally and ignored by Git. An optional SDK-specific bridge supplies read-only permissions, paginated raw reads and the actual SDK change API; the AAR-free build retains the unavailable adapter. Samsung checkpoints contain a change-time watermark and page state, while Health Connect retains its own per-type change tokens. Full snapshots and known-ID reads recheck permissions before deletion reconciliation. SDK UID is retained exactly; export datauuid equivalence requires private overlap validation. Aggregate-only Steps/Activity Summary and metadata-free User Profile remain unsupported as canonical Samsung raw records. See SAMSUNG_SDK_API.md and SAMSUNG_SETUP.md. Physical validation and the seven-day acceptance gate remain mandatory.

Samsung time-window reads reconcile upserts only. The inspected time filter does not prove the exact start-time membership semantics used by Room for unfinished/spanning intervals, so absence from a range is not treated as deletion. Authoritative SDK DELETE events propagate tombstones. Cursor reset also compares known UIDs using unbounded ID-filter reads after all pages and permission rechecks succeed; failed/partial reads cannot delete records. Health Connect retains its documented complete start-window deletion reconciliation. This conservative distinction prevents a range-boundary omission from becoming a false Samsung tombstone.
