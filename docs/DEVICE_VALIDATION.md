# Physical Phase 1 acceptance gate — not yet run

Do not begin Phases 2–6 until seven consecutive days pass without unexplained missing data. No Samsung phone, Watch6, real Health Connect installation, private export or deployed Supabase project has been tested by this implementation session.

Record observations privately. Keep actual health values, screenshots, export files and JWTs out of this public repository. Share only redacted codes/counts when debugging.

1. **Setup:** deploy both migrations/function, create a confirmed Auth account, install the debug APK, enable Samsung → Health Connect sharing, grant reads. Complete the official Samsung bridge first if testing the full two-provider pipeline.
2. **Type inventory:** verify each supported source type against Samsung Health. A type with no observations shows MISSING; unavailable API shows UNSUPPORTED; denied permission shows PERMISSION_REQUIRED. Real RMSSD is required for HRV. Do not use Samsung Energy Score as RMSSD. Check sleep stages separately from sleep sessions.
3. **Provenance:** privately inspect representative local/server records: provider, vendor ID, device metadata, original start/end offsets, created/modified timestamps and raw payload. Health Connect often supplies no physical device UID; it must stay null.
4. **Duplicate/update:** sync the same interval repeatedly. The unique server identity count must not grow. Edit/finalize a supported source record; its row updates and the local queue drains. Samsung and Health Connect versions remain distinct.
5. **Deletion:** delete a test source record; Changes emits a tombstone. Test a deletion found only by complete reconciliation. Failed or permission-limited reads must not delete records.
6. **Offline:** use airplane mode, then foreground Sync Now. Verify raw records and failed/pending queue are durable. Force-stop/relaunch the app; restore connectivity and retry. The exact same records upload once under the correct account. Network failure must not advance upload acknowledgements.
7. **Reboot/background:** reboot with queued records. Ensure WorkManager work survives, eventual upload succeeds, and per-type checkpoints remain. Android timing is approximate; test battery restrictions and background permission separately. Without that permission, verify foreground Sync Now still works.
8. **Cursor expiry/revocation:** exercise an expired token using a debug fake first, then natural expiry if practical. Verify new token is created before the full snapshot; old known deletions reconcile only with sufficient historical access. Revoke permission mid-read: no partial snapshot deletions, no unsafe cursor advancement. Regrant and replay safely.
9. **Queue race:** update a record while an older upload is in flight. The older acknowledgement must not clear the newer revision. Test a server commit followed by client disconnection before acknowledgement; retry must remain idempotent.
10. **Daily reconciliation:** confirm seven-day reconciliation at least once per day when the source can be read. Use the manual last-seven-days action and compare affected IDs privately.
11. **Auth isolation:** sign out with pending records, sign in as a different test account. Original records/cursors/queue must never be uploaded to the second account. Verify database RLS using both JWTs. Invalid JWT, arbitrary user_id and >500 records must fail.
12. **Historical overlap:** import a small supported private subset twice. Verify preserved datauuid and timestamps. Compare a known overlapping live Samsung record using the actual SDK's ID/type mapping. A historical retry must not replace a live row. If IDs differ, stop continuity certification until explicit alias mapping exists. Review per-dataset coverage, quarantined rows, missing sidecars and undated vendor records in the private importer report. Verify missing earlier stages and the missing historical exercise file remain explicit.
13. **Redaction:** copy diagnostics and inspect it: app/source availability, permission names, queue counts and fixed error codes only. No account/device IDs, raw values, notes, locations, source record IDs, source measurement timestamps, passwords or JWTs.
14. **Seven days:** daily compare capture coverage, updates/deletions, queue drain and server identities. Investigate every mismatch. Store a redacted pass/fail acceptance record only after the full gate is met.
