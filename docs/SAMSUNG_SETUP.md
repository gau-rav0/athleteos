# Samsung Health Data SDK setup

The bridge targets the locally supplied official **Samsung Health Data SDK 1.1.0**, in `com.samsung.android.sdk.health.data`. Its public API was inspected before implementation; see [SAMSUNG_SDK_API.md](SAMSUNG_SDK_API.md). Compilation and synthetic tests cannot certify Samsung Health authorization or reads on a Galaxy S21 FE / Watch6. The physical gate remains unrun.

1. Obtain the SDK only from [Samsung's official developer portal](https://developer.samsung.com/health/data/overview.html) and accept its license yourself. Never use unofficial mirrors or the deprecated `com.samsung.android.sdk.healthdata` SDK.
2. Keep the local binary only at `android/app/libs/samsung-health-data-api.aar`; the parent must be a real directory. `git check-ignore -v android/app/libs/samsung-health-data-api.aar` must confirm exclusion. `git ls-files '*.aar'` must return nothing. The backup used to preserve the SDK during repository cleanup stays outside the repository.
3. Build with the local AAR to include the real bridge. An AAR-free build retains a compilation-safe unavailable source instead of pretending vendor reads work. SDK changes require reinspection and rebuild; a renamed incompatible binary is not sufficient.
4. Install/update Samsung Health from its official distribution. Configure developer mode or partner authorization according to the exact SDK and package `com.athleteos.sync`, including its signing certificate. Follow Samsung's [permission request guide](https://developer.samsung.com/health/data/guide/hello-sdk/permission-request.html). Production partner authorization is separate from developer mode.
5. In AthleteOS Home, select **Grant Samsung Health read permissions**. The foreground Activity opens the SDK permission flow using `Permission.of(DataType, AccessType.READ)`. No write access is requested. Health Connect permissions are requested independently. Denial or revocation appears as PERMISSION_REQUIRED; SDK/app availability failures remain explicit diagnostics rather than successful reads. Granting one provider does not hide the availability of the other.
6. Run diagnostics, then Sync Now. Supported raw targets are Energy Score, Exercise, Heart Rate, Sleep, Skin Temperature, Blood Oxygen, Body Composition, and Floors Climbed. Missing observations remain MISSING. SDK 1.1.0 Steps and Activity Summary are aggregate-only; User Profile lacks canonical raw identity/timestamp/source metadata. They remain UNSUPPORTED in this adapter. Steps still come from Health Connect and raw export records remain preserved by the importer. No aggregate total or profile identity is fabricated.
7. Inspect representative records privately: exact SDK UID, source package/device, timestamps/offsets, update time, and versioned raw payload. Missing metadata stays null. The public SDK exposes no creation timestamp or separate end offset; those fields are not guessed. Device lookup failure must not discard the health record. SDK Energy Score never becomes RMSSD.
8. Exercise actual SDK change upserts/deletes, pagination, permission revocation, offline recovery, and complete-window reconciliation. The bridge uses real `readChanges` with a persisted change-time watermark/page state; the common engine retains 72-hour and daily seven-day reconciliation. A failed or partial read must never imply deletion.
9. Compare SDK UID against export datauuid on a known overlapping private record. Matching canonical IDs share the same server identity; differing IDs remain independent until an evidence-based alias mapping is established. Do not infer correspondence from timestamps. See [HISTORICAL_IMPORT.md](HISTORICAL_IMPORT.md).
10. Complete [DEVICE_VALIDATION.md](DEVICE_VALIDATION.md), including the seven-day acceptance gate, before declaring Phase 1 complete. Do not begin Phase 2 analytics.

The AAR, signing keys, private exports, JWTs and health values must stay out of Git. No physical Samsung test or private export validation is claimed by the source implementation.

Samsung time-window reads reconcile upserts only. The inspected time filter does not prove the exact start-time membership semantics used by Room for unfinished/spanning intervals, so absence from a range is not treated as deletion. Authoritative SDK DELETE events propagate tombstones. Cursor reset also compares known UIDs using unbounded ID-filter reads after all pages and permission rechecks succeed; failed/partial reads cannot delete records. Health Connect retains its documented complete start-window deletion reconciliation. This conservative distinction prevents a range-boundary omission from becoming a false Samsung tombstone.
